Seven string helpers in this library are unimplemented stubs that just throw: `camelcase`,
`kebabcase`, `snakecase`, `wrap`, `wrapWith`, `abbrev`, and `initials` — all under
`src/sprig/strings/`, each in its own file. This library is a conformance port: every helper
must produce byte-for-byte the output of the Go original (Masterminds/sprig and the libraries
it delegates to, e.g. huandu/xstrings for the case conversions).

Your task: implement each stub, in its file, so the helper exactly matches the original
behavior — corner cases included (acronym runs, digits inside words, connector and punctuation
handling, boundary widths), not just the obvious happy path.

- Run `pnpm install --frozen-lockfile`, then `pnpm test` and `pnpm typecheck` — the visible
  gates. They must pass.
- Your work is then scored against a **held-out conformance corpus**: fixture templates you
  cannot see, whose expected output was generated by running the real Go implementation.
  Passing the visible gates is necessary but not sufficient — only faithful semantics survive
  the held-out corpus.
- `conformance/gen/` contains the Go reference generator that corpus was built with: point it
  at fixture dirs (`template.tmpl` + optional `scope.json`) and it writes each `expected.txt`
  from the real Go implementation. If a `go` toolchain is available you can write your own
  fixtures and use it as an oracle.
- Do not modify or delete existing tests, conformance fixtures, or config files; implement the
  library source only.

You are done when the visible gates pass and your implementations faithfully match the
reference semantics on inputs beyond the visible tests.
