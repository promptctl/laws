# Craft conflict edges — the authoritative compatibility policy for the laws plugin.
#
# One DIRECTED edge per line, bare craft names (no "laws:" prefix), read left to right:
#
#     <engaged>  <refused>
#
# means "while <engaged> is loaded, refuse an incoming <refused>". The reverse order is a
# DIFFERENT statement and is not implied — an edge here says nothing about loading these
# two the other way round. EVERY ordering absent from this list may coexist.
#
# THE ORDER IS THE WHOLE POINT, and it was wrong once. This policy used to be a set of
# symmetric pairs, which refused the reverse direction too. That is a false refusal, and an
# expensive one: the guard would deny a legitimate load and cost the user a fresh session to
# escape a conflict that does not exist. Symmetry also hid a live defect — a caller could pass
# its arguments in the wrong order and nothing could tell, because the predicate could not
# distinguish them. Keep the direction; it is load-bearing, not bookkeeping.
#
# This is a SHORT list by design — not a full NxN matrix, and not an "exclusive" craft —
# naming only an ORDERING shown to break real work. Add an edge only with the same kind of
# evidence, and only in the direction the evidence supports.
#
# Read by skill-router.sh — the PreToolUse guard that refuses the conflicting 2nd load — so
# the rule has exactly one home ([LAW:one-source-of-truth]). Changing the policy is editing
# THIS file; the guard hard-codes no craft name.
#
# Blank lines and lines beginning with '#' are ignored; a trailing '# comment' is stripped.
